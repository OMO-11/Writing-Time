## 3. 优先修改建议

优先级：P0 为内容丢失或导入安全问题，先于功能扩展；P1 为核心工作流缺口，建议下一轮修复；P2 为体验、性能与维护改进。工作量仅用小/中/大表示相对规模，不是交付承诺。

### R01 · P0 · 统一详情页的可靠保存（中）

**证据：** `components/content/ContentDetail.tsx:42`、`:46`。详情页使用 700ms 定时保存，effect 清理直接取消定时器，未注册全局 `flushSave`。请求成功时直接 `setDraft(next)`。

**影响：** 编辑设定卡、灵感等内容后立刻导航，最后输入可能未落库；旧保存请求返回时，可能把期间新输入替换成旧草稿。代码路径已确认，竞态需受控延迟复现。

**建议：** 抽出统一保存控制器，以内容 ID 和修订号管理队列；成功响应只确认对应修订，不覆盖较新草稿。所有编辑器注册离页刷新，导航等待队列保存到最新修订；失败时保留草稿并允许重试。异步派生索引失败与正文写入失败分开提示。

**验收：** 输入后 200ms 内离页再返回，内容仍在；模拟慢保存期间继续输入，末尾文字不被回滚；写入失败时不显示“已保存”。

### R02 · P0 · 校验备份，并拒绝信任导入 HTML（中）

**证据：** `lib/export-service.ts:42` 仅检查 format 和两个数组，然后直接写入 `renderedHtml`、`excerptHtml` 等字段；`components/markdown/MarkdownRenderer.tsx:27` 和 `MarkdownExcerpt.tsx` 直接插入 HTML。`lib/db.ts:238` 对定稿文章跳过重新处理。

**影响：** 导入外部或被修改的备份，存在持久化 HTML 注入风险；缺失字段、未知版本、异常 payload 也可能使恢复或页面失败。这是可达代码路径判断，本轮没有对实际数据库执行攻击验证。

**建议：** 入库前校验格式版本、各内容类型字段、大小和引用目标；HTML、摘要和标题索引作为派生数据，从 Markdown 重新生成并清理。定稿正文仍不可修改，但导入时的安全校验不能跳过。展示端保留统一的 HTML 信任边界。

**验收：** 含事件属性、危险 URL、伪造摘要及定稿标记的备份不能引入可执行 HTML；不支持的版本在写入前报错，原数据库保持完整。HTML 输出边界的依据见 [OWASP XSS 防护说明](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html)。

### R03 · P1 · 自动保存同步引用，并保护定稿图片（中）

**证据：** `components/workbench/Workbench.tsx:115` 写入 works、contents、activity，之后重建搜索，却未调用引用重建。引用维护在 `lib/content-service.ts:42`。图片删除界面允许 `deleteImageAsset(id, true)`；该服务位于 `lib/content-service.ts:167`，未按定稿引用区分保护。

**影响：** 自动保存后新增/删除图片与 Wiki 链接，引用列表可能过时；即使正文被锁定，图片仍可强制删除，恢复备份也会直接覆盖同 ID 图片，定稿视觉内容可能改变。

**建议：** 将正文保存和引用边维护纳入同一服务；删除前检查最新引用，定稿使用的资源默认不可破坏。可先采用“阻止删除/覆盖定稿引用图片”，后续再设计内容哈希与不可变资源版本。书籍关系也纳入统一引用查询。

**验收：** 插入与移除图片后引用数立即正确；文章标题变化后双链状态可解释；定稿作品和已编书内容中的图片不会被普通删除或恢复合并悄悄替换。

### R04 · P1 · 补齐导出的资源完整性（中）

**证据：** `lib/export-service.ts:68` 仅按原图片名写 ZIP；`:81` 的旧项目导出未遍历成员文章正文图片，文章也按标题命名；`:110` 的静态 HTML 原样使用带 `fw-asset://` 的 HTML。

**影响：** 不同图片同名时覆盖，文章同名也冲突；导出成功但图片缺失，离开应用后无法独立阅读。ZIP 同路径覆盖已用当前依赖验证。

**建议：** 用稳定 ID + 安全文件名生成唯一相对路径，输出资源映射表并重写 Markdown/HTML 链接；递归收集实际依赖并去重、处理循环。静态 HTML 选择内嵌图片或 HTML+assets 包；缺失资源在导出前列出。

**验收：** 两张同名图片、两篇同名文章、正文图片、封面及嵌套内容都能保留；在空白浏览器或断网环境打开导出物，图文完整。

### R05 · P1 · 备份采用一致快照，恢复展示真实结果（中）

**证据：** `lib/export-service.ts:31` 并行读各表，books 又单独读取，未使用覆盖所有表的只读事务。`:42` 合并恢复会跳过已定稿文章，但返回原始备份数量；设置页仍提示同 ID 内容均会被覆盖。新数据库 schema 已为 v4，备份格式仍为 v3 加可选 books。

**建议：** 保存队列刷新后，在同一只读事务中获取数据快照，再在事务外编码 Blob。数据库版本与备份格式版本分别管理并记录兼容规则；恢复前预览新增、覆盖、跳过、冲突和无效引用数量；为书籍校验章节与定稿作品关联。大备份增加进度和取消，逐步评估 ZIP+二进制资源方案。

**验收：** 写作与备份并发不会导出跨版本内容和书目；定稿跳过数量显示准确；失败回滚完整。`replace=true` 是服务层现有参数、当前界面未暴露，启用前单独验证其与定稿删除 hook 的冲突。

### R06 · P1 · 修复 Wiki 小节定位和同名解析（中）

**证据：** `lib/markdown-service.ts:114` 为大纲生成 id，但 `renderHtml` 未将其写到实际标题元素；相同渲染链最小验证未产生标题 id。`components/content/WikiRedirect.tsx:16` 会附加 hash。引用重建按 Map 取同名最后一项，跳转查询却取第一项，目标可能不同。

**建议：** 共用标题 slug 与重复标题编号逻辑，生成可访问的真实 HTML 锚点，并校准清理器允许的 id；稳定 ID 作为关系身份，标题作为显示名。遇到重名提供选择，保留别名或重命名映射；从语法树提取 Wiki，避免把代码示例当成关系。大纲位置还需保留 Frontmatter 与 Wiki 展开前的源码偏移。

**验收：** 中文标题、重复标题、含 Frontmatter 的文章、小节链接、重命名和同名内容均定位正确，代码块示例不产生伪引用。

### R07 · P1 · 让恢复快照真正可用（中）

**证据：** `lib/db.ts:340` 和 Workbench 已每 30 秒创建快照并清理 24 小时前数据；本轮对 app/components 的检索未发现快照选择、比较或恢复界面。

**建议：** 编辑器增加“恢复历史”，先支持按时间预览、比较、恢复为新草稿；仅内容变化时写快照，保留少量关键版本。启动时发现快照晚于已保存正文，明确提示可恢复。保留已有定稿不可修改规则。

**验收：** 能找回较新的快照，恢复不覆盖原稿；定稿快照只能生成新草稿；长期停留不重复堆积相同正文。

### R08 · P1 · 加强保存中的切换和多标签页一致性（中）

**证据：** `Workbench.tsx:90` 在保存进行中返回现有 Promise，`:261` 等调用等待一次后切换。其间产生的新修订可能仍然 dirty。通用内容和书籍都使用整个对象 put，未见数据库修订号比较。

**风险：** 大文档处理较慢时，离页可能只等到旧修订；两个标签页编辑同一作品或书目，后写入者可能覆盖另一页更新。

**建议：** flush 循环等待当前 ID 的最新修订落库；保存事务比较 baseRevision，冲突时保留双方副本。跨标签页消息用于提醒，数据库条件检查才是最终保护。已有 blur/visibilitychange 保存应保留，但不能承诺关闭时异步保存必然完成；[MDN 说明 beforeunload 并非可靠的最后保存时机](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)。

**验收：** 慢处理期间继续输入并切换作品，不串稿、不丢尾部输入；两个标签页同时改书目或正文时出现明确冲突处理。

### R09 · P1 · 修正定稿后的收藏与保存反馈（小）

**证据：** `ContentDetail.tsx:52` 的收藏通过整份草稿触发 `saveContent`，而 `lib/db.ts:136` 只允许定稿内容单独修改 favorite；`saveContent` 还更新 updatedAt，因而被保护拦截。`BookProjects.tsx:56` 在失败后 busy 变 false，状态仍可能显示“目录已保存”。

**建议：** 收藏复用已有 `toggleFavorite`，区分不可变作品字段与可变个人整理信息。书籍采用明确的 saved/saving/error 状态。定稿内容的全部入口统一显示阅读行为。

**验收：** 从定稿详情页收藏成功，正文与元数据未变；书目保存失败时不出现成功文案。

### R10 · P2 · 统一路由、缺失状态和名称（小至中）

**证据：** `/library?type=project` 已重定向，但 `/content?type=project` 仍把 project 传给排除项目的列表；标题栏仍混用作品库、内容工作区、工作区。`WorkDetail.tsx:20` 和 `ContentDetail.tsx:49` 将查询未完成与查无结果的 undefined 混用。图片搜索地址为 `/gallery?image={id}`，Gallery 当前只处理 upload 参数，未消费 image 参数。

**建议：** 统一“工作区 / 书籍项目 / 旧创作项目 / 图片资源库 / 拾光画廊”的命名与用途；旧入口一致重定向。查询返回明确的 loading/not-found/error/ready 状态；图片搜索命中后定位目标或打开灯箱。

**验收：** 旧项目链接有效；不存在的 ID 显示可返回的缺失提示；搜索图片能直达目标；面包屑与导航一致。

### R11 · P1 · 切换设定模板时保留填写内容（小至中）

**证据：** `components/content/RecordEditor.tsx:11` 的 `changeTemplate` 直接用 `createRecordFields(template)` 替换整个 fields 对象；原先填写的字段没有迁移或暂存，随后会触发详情页自动保存。

**建议：** 保留同名字段，把其他字段暂存为扩展字段或各模板独立草稿；切换前说明受影响字段，支持取消和撤销。优先修好此行为，再新增个人模板。

性能目标先作为待测标准：在声明的设备上，以 1,000/5,000 条内容、长篇中文文稿和大批图片建立样本，记录输入延迟、保存延迟、搜索 p95、初始内存、导出峰值。可先以搜索 p95 小于 150ms、交互反馈小于 100ms 作为目标；这些不是本轮实测结果，图片 Blob 规模需另行说明。

环境方面，应优先核对 Node 与可选原生依赖的架构一致性，保留锁文件并采用可复现安装流程；不建议把“删除所有依赖和锁文件重装”当作默认修复。当前任务仅记录阻塞，没有改变环境。

## 6. 界面体验建议

1. **保留沉浸入口，同时减少重复进入成本。** 地图的美术已具备辨识度；在合适位置提供“继续上次写作 / 最近书籍”，让重复使用者快速进入正文。
2. **把三种保存结果说清楚。** 自动保存表示保存在当前浏览器；完全保存表示锁定定稿；导出备份表示生成可迁移文件。按钮旁使用简短说明，并持续显示失败状态。
3. **书架增加明确的选中与恢复上下文。** 刷新后回到上次书籍/章节，书籍选择写入 URL 或本地偏好；把原生 prompt 逐步替换为可校验、可键盘操作的轻量表单。
4. **移动编订优先可操作性。** 章节折叠、较大的排序按钮、可搜索的作品选择；多章节长目录避免每行都摆放完整操作栏。需实际检查 360px、390px 及横屏，而非只检查无横向溢出。
5. **动效与可访问性共同验收。** 保留减少动态效果；验证地图目的地、弹层、灯箱和书目操作的键盘焦点、Escape 行为和读屏名称。新拖拽功能必须保留按钮方式。
