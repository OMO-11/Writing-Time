# Writing Time 首页 Ambient Life 动态增强任务

## 0. 任务身份与最高原则

你正在维护项目：

`OMO-11/Writing-Time`

这是一个已经存在并可以正常运行的项目，不是新项目。

本任务的目标不是重新设计首页，不是重构渲染系统，也不是把页面改造成 Live2D、3D 游戏或动态壁纸。

本次任务唯一目标：

> 在保持当前 Writing Time Portal 的构图、美术、导航、WebGL 重光照和整体视觉语言不变的前提下，让当前诺瓦尔书房背景拥有持续但克制的“生命感”。

用户不操作页面时，也应该能够感受到：

* 人物会自然眨眼；
* 人物存在非常微弱的呼吸；
* 不同区域的头发会受到轻风影响；
* 偶尔会出现一阵稍明显的风；
* 浮尘持续漂浮并形成远近层次；
* 窗外环境存在非常缓慢的变化；
* 页面光照会围绕现实时间发生很轻微的漂移；
* 所有动态互相协调，而不是各自动画。

最终体验应该是：

> 第一眼仍然是一幅安静的插画，但观察几秒到几十秒后，会发现这个房间其实一直“活着”。

不要让用户产生“网页背景动画很多”“视频壁纸”“Live2D 人物”的感觉。

# Phase 1：自然眨眼系统

当前已有闭眼图片：

```text
/assets/home/noval-observatory-closed.png
```

当前已有闭眼 texture 混合。

继续复用。

但是不要继续使用完全固定的：

```text
13.7 秒周期
固定三个时间点
```

改为“确定性伪随机眨眼调度”。

建议行为：

```text
下一次眨眼间隔：
3.5 ~ 8.0 秒

普通单眨：
约 85%

双眨：
约 12%

稍长闭眼：
约 3%
```

时间建议：

普通眨眼：

```text
闭合 60~90 ms
保持 30~60 ms
睁开 80~120 ms
```

双眨：

```text
blink
120~180 ms pause
blink
```

长闭眼：

```text
约 300~450 ms
```

不要使用真正随机导致每次 frame 不稳定。

使用：

```text
seeded pseudo-random
```

或者在 JS 层生成下一次事件时间。

目标：

人物看起来是在自然眨眼，而不是循环 GIF。

# Phase 2：头发分区域动态

当前：

```text
animatedUv()
```

已经存在。

不要删除。

但当前整体偏移太弱且区域结构不明显。

将头发拆成几个“逻辑运动区域”。

不要求新增纹理。

可基于现有：

```text
region()
颜色特征
UV 范围
```

构造 mask。

建议至少区分：

```text
bangs / front hair
side hair
side ponytail
hair tips
```

动态层级：

### 刘海

幅度：

```text
非常小
```

特点：

```text
稍快
轻微
避免扫过眼睛
```

---

### 主体头发

幅度：

```text
小
```

特点：

```text
缓慢
平滑
保持整体形状
```

---

### 发梢

幅度：

```text
中等
```

特点：

```text
比主体头发稍有延迟
稍强
```

---

### 侧马尾 / 较自由发束

幅度：

```text
最高
```

但仍然必须克制。

不要超过让用户察觉“图片变形”的程度。

参考原则：

```text
主体移动 < 发梢移动 < 自由发束移动
```

每个区域使用不同：

```text
frequency
phase
amplitude
```

避免：

```text
整块头发一起左右移动
```

# Phase 4：阵风系统

这是本次非常重要的新增部分。

建立统一：

```text
windStrength
```

概念。

不要让不同 Shader 各自完全独立地产生风。

基础风力长期保持：

```text
0.1 ~ 0.2
```

偶发阵风：

```text
每 15 ~ 40 秒一次
```

持续：

```text
2 ~ 4 秒
```

典型曲线：

```text
0.15
↓
0.35
↓
0.65
↓
0.45
↓
0.15
```

必须使用平滑曲线：

```text
smoothstep
sin
cubic easing
```

不能突然改变。

windStrength 同时影响：

```text
发梢
侧马尾
少量衣角
浮尘横向速度
```

形成统一环境事件。

目标：

偶尔给人感觉：

> 窗口吹进来一阵很轻的风。

不要加入：

```text
强风
大幅摆动
持续摇晃
```

# Phase 5：浮尘空间层次

当前已有：

```text
dustCount ≈ 420
```

原则上不要增加数量。

重点是提高：

```text
depth perception
```

而不是提高：

```text
particle count
```

建议将现有 seed 分为三个视觉层：

```text
far
mid
near
```

例如：

```text
far  ≈ 65%
mid  ≈ 27%
near ≈ 8%
```

远层：

```text
尺寸最小
移动最慢
透明度最低
```

中层：

```text
当前主要浮尘
```

近层：

```text
数量很少
稍大
稍柔
稍快
```

近层不能遮挡人物脸。

继续保留 face clearance。

浮尘运动：

```text
slow upward drift
+
horizontal wind
+
small turbulence
+
depth-dependent speed
```

进入光束：

```text
brightness ↑
```

离开光束：

```text
brightness ↓
```

不要：

```text
随机闪烁
像雪
像星星
像萤火虫
```

它应该仍然是：

```text
indoor dust
```

# Phase 6：窗外缓慢环境运动

目标：

解决“室内特效在动，但窗外还是一张静止图片”的问题。

不要求生成新资产。

首先尝试基于现有画面做：

```text
window-area-only shader movement
```

只允许作用于：

```text
天空
云雾
远景 atmosphere
```

不要作用：

```text
窗框
人物
桌面
室内建筑
```

建议：

### 云层

非常轻微横向 UV drift。

周期尺度：

```text
几十秒 ~ 数分钟
```

位移必须极小。

---

### 远景薄雾

使用：

```text
low-frequency noise
```

产生极轻微：

```text
density variation
```

不要制造明显的程序噪声。

---

### 窗外亮度

允许非常小幅：

```text
±2~4%
```

缓慢变化。

可以理解为：

```text
云层经过太阳
```

但不要造成闪烁。

# Phase 7：Ambient Time Drift

这是最推荐加入的宏观动态。

当前：

```text
target.hour = real time
```

不要改变 UI 显示的真实时间。

新增：

```text
sceneHour
```

概念。

默认：

```text
sceneHour =
realHour
+
very small slow offset
```

建议：

```text
偏移范围：
±0.25 ~ ±0.4 hour

即约：
±15 ~ ±24 分钟
```

周期：

```text
约 4 ~ 8 分钟
```

例如：

```text
sceneHour =
realHour
+
sin(t / longPeriod) * 0.3
```

但是：

不要让真实时间和 sceneHour 永久漂移。

应始终围绕：

```text
realHour
```

摆动。

作用：

Normal Map Lighting 会持续产生非常缓慢变化：

```text
太阳方向
人物明暗交界
发丝柔光
窗光
光束
浮尘受光
```

这样用户即使完全不触摸时间滑块：

```text
WebGL relighting
```

仍然具有存在意义。

# 21. 最终目标状态

最终页面应该产生这样的体验：

### 进入页面

看到：

```text
安静的诺瓦尔书房
```

第一印象仍然是一幅完整插画。

---

### 几秒后

注意到：

```text
诺瓦尔眨眼
浮尘慢慢经过光束
发梢轻轻移动
```

---

### 十几秒后

能够隐约感受到：

```text
呼吸
头发不同部位不是完全同步
窗外空气并非完全静止
```

---

### 偶尔

出现：

```text
一阵轻微的风
```

此时：

```text
发梢
侧马尾
衣角
浮尘
```

产生一次一致响应。

---

### 数分钟后

用户如果一直停留，会发现：

```text
窗边光线
人物明暗
发丝高光
光束
```

已经和刚进入时有一点差别。

但页面上的真实时间没有失真。

---

最终不要让用户觉得：

> “这个网页动画做得很多。”

而应该让用户觉得：

> “这个房间好像真的一直在呼吸。”

这就是本次修改的唯一视觉目标。
